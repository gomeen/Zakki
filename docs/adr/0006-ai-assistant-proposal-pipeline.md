# AI 助理采用「建议管线」：动作归约为文本编辑，确认后才应用

Zakki 要接入 AI：用户一句自然语言（「帮我增加一个提醒」「把分工那段整理成待办」），
应用做出对应改动。参考对象是 Notion 的 agent——先给方案、可确认、可调整——但 Zakki 是
便签应用，交互必须克制；同时它是本地优先的单二进制，没有自有服务端。

核心判断：**Zakki 的 agent 不需要工具调用基础设施**。笔记本身就是工具面——

- 笔记是 Markdown 纯文本，一切内容操作都归约为「插入行 / 替换锚点行 / 新建标签写内容」
  三种动作；
- 提醒不需要专门通道：带时间令牌（`@YYYY-MM-DD HH:mm ~提前量 ^规则`，ADR-0001/0002）
  的任务行就是提醒，现有调度器自动接手——「加提醒」= 让模型写一行原生文本。

## 决策

1. **建议管线而非工具调用**。`internal/ai`（纯逻辑）把指令 + 当前标签快照发给
   OpenAI 兼容 `chat/completions`（非流式，全走用户配置的端点：OpenAI / DeepSeek /
   OpenRouter / Ollama 本地 / 自定义），要求模型只回一个 JSON：一组带锚点的结构化
   建议。锚点必须从笔记原文逐字复制，包内做唯一性校验（`strings.Count == 1`），
   校验失败如实报错，不做本地 diff 兜底。
2. **确认式交互（助理条）**。主窗口底部单行输入（⌘⇧A / 底栏 ✦ / 编辑菜单）→
   建议卡堆叠（最多渲染 4 张）：类型徽标 + 落点说明 + 渲染预览（替换类红删绿增 diff，
   提醒类显示令牌胶囊与「将于 … 提醒」），逐卡「应用 / 放弃 / 编辑原文」或多卡
   「全部应用」。不做聊天记录 UI——便签不长对话窗口。
3. **应用走既有编辑事务**。insert/replace 换算为行级变换经 `runAsCommand` 独立撤销
   事务（⌘Z 可退）；应用时对锚点复查唯一性。newTab 追加标签写入内容，不自动切换、
   不可 ⌘Z（撤销历史属当前标签），toast 如实说明。
4. **失效策略：指纹丢弃**。发送时拍全文快照；交付时正文或标签变了就丢弃建议并提示
   「内容已变化，请重新提问」。切标签清空整条。不做过位重定位——保守但零歧义。
5. **调整两条路**：底部追问（上一轮指令与建议作为上下文重发，整组替换）或卡内
   直接编辑建议的 Markdown 原文（看到真实令牌语法，强化「文本即数据」）。
6. **凭据与隐私沿用 R7**。偏好 ai 节（版本 16）只存开关/提供方/端点/模型名；
   API 密钥只进系统安全存储（`Zakki AI`/`apikey` 条目，Windows 走 ai-key.bin）。
   只发送当前标签文本与标签名（超长截中间）；本地 Ollama 不出本机。
7. **建议卡配色随主题**。diff 红绿墨色从颜色主题派生（不足 4.6:1 时向主题正文色
   收敛，覆盖全部主题 × 明暗 + 经典七点派生盘的对比度测试把关），sketch/claude/qoder
   有随主题基调的锚点覆盖；手账风格卡片用铅笔描边。

## Considered Options

- **行内批注（建议卡嵌在正文目标位置，原型 B）**：上下文最直观，但要侵入虚拟化块
  列表、处理正文编辑期间的锚点漂移，工作量约多三分之一。留作二期增强，第一版只在
  卡片内呈现 diff。
- **选区气泡（原型 C）**：直接操纵感好，但对全文级任务（总结、拆标签）无入口。
  拒绝作为唯一交互。
- **工具调用架构（function calling / 本地工具注册表）**：为「改文本」引入工具协议、
  权限与执行沙箱，复杂度远超收益；文本编辑归约让撤销、失效、渲染全部复用既有管线。
- **本地 diff（LCS/Myers）兜底**：模型返回的锚点就是它要改的原文，本地 diff 只在
  模型答错时才有用；答错应当报错重试，而不是默默算一个模型没提议的 diff。
- **流式输出**：建议必须整体校验（锚点、JSON 形状）后才能呈现，流式只省等待尾部，
  却把解析与失效判断复杂化。二期再议。
- **云端自带模型**：与本地优先定位冲突，也引入服务端成本与隐私面。拒绝。

## 后果

- 新增 `internal/ai` 纯逻辑包（零依赖，`make arch-check` 纳管）与 `internal/app`
  的 ai_* / view_ai_bar / settings_ai 五个文件；偏好版本 16（缺键零值，无迁移逻辑）。
- 模型行为不可控的风险由结构兜底：锚点唯一性校验、≤4 渲染上限、指纹失效、
  确认式应用、撤销事务、密钥不落盘（泄漏扫描测试）。
- 每次请求都会把当前标签文本发往用户配置的端点，设置页明示数据流向。
