# 同步冲突改为自动合并，不再留档

Zakki 的云同步（GitHub Contents API，单文件 `zakki.json`）此前沿用移动端规格的 D13 决策：
本机与远端都相对基线变化且内容不同时弹原生对话框二选一，落选版本完整留档到
`conflicts/zakki-YYYYMMDD-HHmmss-<设备名>.json`。实际使用后有两个问题：

1. 冲突几乎总是「同一用户换设备太快」造成的，不是真正的并发编辑——本机要等
   保存（2s）加同步防抖（10s）才推送，12 秒内切到另一台设备就会制造冲突；
2. 冲突留档目录与「桌面便签只留最少文件」的目标冲突（用户明确提出不想要它）。

## 决策

1. **触发时机先补齐，让冲突基本不发生**：保存后的同步防抖从 10s 缩到 3s；主窗口
   失焦/隐藏时若有未推送的本地修改立即保存并推送（限频 5s）；主窗口聚焦时拉一轮
   （限频 30s，原先只有热键/托盘/Dock 唤起才拉）；退出时在最终保存后尽力推送一轮
   （上限 3s，超时或失败照常退出，下次启动按判定表自动补推）。
2. **双方都改时自动合并，取代弹窗与留档**：以基线保存的上次同步原文为公共祖先，
   按标签稳定 ID 逐条三方合并（`internal/notes/sync_merge.go`）——只有一边改的标签
   取改的一边；两边都改的标签按修改时间较新者胜（本机文件 mtime vs 远端最近提交的
   committer 时间）；一边删、另一边没动的标签删除；一边删、另一边改的保留改动；
   两边各自新建的标签都保留（撞号时较旧一侧换新 ID）。当前标签跟本机走。settings
   与顶层未知字段各作为整体三方合并（只一边改取改的一边）。合并结果写盘、上传并
   提示「已合并其他设备的修改」。
3. **退化路径**：缺基线原文（旧基线只存指纹）、任一侧解码失败、合并结果超标签上限
   或回验失败时，退化为整个文件较新者胜，不写坏文件。
4. **从未同步过的设备以云端为准**：首同步时本机与远端都有内容直接采用远端，
   新设备上的欢迎文本不会覆盖云端笔记。
5. **删除冲突留档及其 UI**：`conflicts/` 目录、二选一对话框、设置页留档列表与删除
   入口全部移除；基线状态文件 `sync-state.json` 由此多存一份上次同步原文（合并的
   公共祖先），仍是唯一额外文件。
6. 本决策取代移动端规格 D13 的桌面实现；移动端已冻结（ADR-0003），不随之修改，
   恢复移动端时需重新对齐。

## Considered Options

- **照搬腾讯文档的实时 OT/CRDT**：拒绝。OT/CRDT 需要常驻中心服务器接收每次按键并
  广播，Zakki 的后端是 GitHub Contents API，只能整文件读写，无服务器无长连接。
  可借鉴的只有「改动尽快离开本机」（决策 1）与「按结构单元合并」（决策 2，
  Notion 按块合并的同思路）。
- **Obsidian 式 diff-match-patch 全文三方合并**：拒绝。合并两个完成态文本等于猜测，
  Obsidian 官方文档也承认会产生重复文本。zakki.json 本身就是带稳定 ID 的标签数组，
  按标签合并是精确的，不需要猜。
- **无提示 LWW（整文件较新者胜）**：保留为退化路径而非主路径。逐处合并能保住
  「这台改 1 号标签、那台改 3 号标签」的常见情形，代价只是基线多存一份原文。
- **保留二选一弹窗但去掉留档**：拒绝。单人使用场景下弹窗只会打断输入，且预设
  「同一时间只在一台设备编辑」，真冲突时自动较新者胜的代价可接受。

## Consequences

- 同一标签两边都改且较旧一侧被丢弃时，**没有任何找回手段**——这是「不写留档文件」
  的直接后果，也是本决策唯一的数据丢失面。GitHub 仓库本身的历史提交是兜底
  （每次 Push 都是一条 commit）。
- 较新者胜依赖两侧时钟大致可信；偏差超过「两边编辑间隔」才会判错方向，远端时间
  取 GitHub 记录的 committer 时间，不受本机改钟影响。查不到远端时间时按本机较新。
- 基线文件大小约等于笔记本身（多存一份原文），仍是设备本地单文件。
- 退出最多多等 3 秒（有未推送修改且网络慢时）；正常情况不碰网络即刻退出。
- `SyncConflict` / `ResolveSyncConflict` / `ConflictsDir` / `ListConflictArchives` 等
  API 移除；`SyncState` 新增 `LastMerge` 区分「应用远端」与「合并两端」的界面提示。
