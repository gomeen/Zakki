# Zakki アーキテクチャ

後続のメンテナーと agent 向け：コードを変更する前に本文を読んでください。本文は安定した事実のみを記述し、具体的な挙動はソースコードを正とします（要点にはファイルと関数を明記しています）。
プロジェクトは[MyGo](https://github.com/egoist/mygo) ネイティブ Go UI のデスクトップアプリで、HTML/JS/webview を使わず、
純粋な Go の単一バイナリです。

プロジェクトは 2 層に分かれます：`internal/app` は UI とアプリの組み立て（MyGo に依存してよい唯一の internal パッケージ）；
`internal/` の残りのパッケージは純粋ロジックと永続化で、MyGo と `internal/app` への依存は禁止です。ルートディレクトリにあるのはエントリ `main.go` だけです。

依存は標準の `vendor/` で固定しています。MyGo のバージョンは [`go.mod`](../../go.mod) を参照してください。ネイティブ文字区間スタイルのパッチは `patches/mygo-text-range-background.patch`、
インラインオブジェクトのサイズと実際のジオメトリのパッチは `patches/mygo-textinput-objects.patch`、ショートカットがエディタの単語間移動より優先される
キールーティングのパッチは `patches/mygo-shortcut-claimed-keys.patch`（⌘数字でタブを切り替えた後もエディタがフォーカスを保持し、⌘⌥←/→ でタブを巡回できる）、
日付パネルの列幅と行間のパッチは `patches/mygo-calendar-spacing.patch` です。依存の更新には `make vendor` を使い、
保守上の制約は[依存パッチ](../../patches/README.md)（中国語）を参照してください。フォント／斜体／フォントの太さはネイティブのレイアウトに入り、下地色／色／下線は描画にのみ関与します；
区間のマージ、IME、選択範囲、スクロールは引き続き入力コントロールを再利用し、別のテキストレイアウトは作りません。

## モジュールの責務

| ファイル | 責務 |
|---|---|
| `main.go` / `internal/app/lifecycle.go` | エントリ `app.Run()`：単一インスタンス、ログ（stderr のみに書き、ディスクには残さない）、起動時にクラッシュの残骸テンポラリファイルを掃除（`temp_sweep.go`）、macOS メニュー（アプリ/段落/フォーマット/編集/表示/ウインドウ）、トレイ、グローバルホットキー、終了とアップデートの後処理；メインウインドウは mac では枠なしの自前描画タブバー、Windows ではタイトルバー非表示モード（`TitleBarStyle: hidden`）でネイティブの最小化/最大化/閉じるを残し（`StateKey: "main"`）、閉じるとトレイに常駐し、`OnActivate` が `showWindow` を再利用。メニュー項目とショートカットの詳細は `menu_commands.go`、`menu_edit.go` と [環境設定](configuration.md)。 |

| `internal/app/updates.go` | MyGo `plugins/updater/native` のネイティブ更新ウインドウを登録（インターフェース言語に従い、既定は手動チェック）；アプリメニューとトレイが「アップデートを確認…」を提供する。`finishQuit` により更新後の再起動も最終保存を経由し、失敗すれば終了をキャンセルする。更新用公開鍵と `gomeen/Zakki` の配布先は `mygo.json` にあり、tag は全件チェックの後、macOS universal と Windows x64 をそれぞれビルドし、両プラットフォームが成功した時点でドラフト Release にまとめる。手順は `.github/workflows/release.yml`、操作は [リリース](release.md) を参照。 |
| `internal/app/prefs_runtime.go` / `internal/app/prefs_bridge.go` | 環境設定の実行時統合：`loadPreferences`/`updatePreferences`。ディスクへの書き込みは `prefs.Store` に委譲。型エイリアスは `prefs_bridge.go`。 |
| `internal/app/notes_bridge.go` | ノートのディスク型エイリアス（`settings`/`savedTab`/`savedFile` など旧設定のエイリアスもこのファイル）と `migrateSavedFile`、`newNotesStore`。 |
| `internal/app/storage_file.go` / `internal/app/settings_storage.go` | 唯一のノートファイル：`validateStorageDir`（ディレクトリの書き込み可否プローブ）、`chooseStorageDirAsync`（バックグラウンドでディレクトリ選択ダイアログを出し、ウインドウの `Update` でメインスレッドへ戻す）；`applyStorageDir` は実行時の安全な移転——直列な `Relocate`（既存の移動先への上書きを拒否 → 候補を書き込んで検証 → 環境設定の永続化に成功してから正式パスを切り替え → 旧ファイルを削除、失敗時は元ファイルを保持して正直にエラー報告、同一パスは no-op）；「保存と同期」ページはファイルパス、保存状態、Git スイッチを表示。初回セットアップウィザードと設定ページで共用。 |
| `internal/app/onboarding.go` / `internal/app/onboarding_view.go` | 初回セットアップウィザード（新規インストールのみ、`firstRun` = データファイルが存在しない）：640×560 の独立ウインドウ（`StateKey: "onboarding-v2"`）、2 ページのドラフト式確認——① 言語（English/日本語/简体中文/繁體中文、選択で即座に `App.SetLocale` を呼び環境設定に書き込み）、明暗、スタイル（標準/スケッチブック、`appearance.style` に書き込み、フォントは強制しない）、中国語フォント、英語フォント（初期選択 JetBrains Mono）；② 初期タブ数 1〜9 とノートの保存先（現在のデータディレクトリをプリセット、変更可能、常に表示；完了時に `Relocate` で選択フォルダの `zakki.json` へ移し `storage.dataFile` を永続化）。選択はダウンロードを起こさない；主ボタンは「設定を完了」または「フォントをダウンロード」を表示し、送信後にドラフトを凍結、不足フォントは `prepareFonts` で一括ダウンロード（全体進捗と個別フォント進捗）、完了後に準備完了ページに留まり、「書き始める」を押して初めて環境設定と初期データを書き（`commitFirstRunData` の意味論、失敗時はウィザードに留まる）メインウインドウへ進む；失敗時は再試行、戻って修正（旧ダウンロードバッチを無効化）、またはシステムフォントへの切り替えが可能。ウインドウを閉じる際は設定の続行、既定設定の使用、アプリ終了を明示的に尋ねる；設定未完了で終了を選んだ場合もアプリを直接終了した場合もノートは作成せず、次回起動時にもウィザードを表示；歓迎文はタブ数に応じて生成（`welcomeTextFor`）；メインウインドウはウィザードの終了後に作成。 |

| `internal/atomicfile` | ノートと環境設定が共用する永続書き込み：同一ディレクトリのランダムなテンポラリファイル → 全体を書き込み → `Sync` → `Close` → rename → `SyncDir`；rename 後の同期失敗は `CommitError` / `IsCommitted` で移動先が置換済みであることを示す。Windows ではディレクトリハンドルの同期を行わない。`sweep.go`：テンポラリファイル名の接頭辞 `TempPrefix` と、接頭辞+更新時刻でクラッシュ残骸を削除する `RemoveStaleTemps`。 |
| `internal/sysnotify` | 未パッケージ実行時のフォールバック通知配信（MyGo 依存なし、ADR-0005）：macOS は argv 付き osascript、Windows は固定 AUMID の PowerShell WinRT toast（タイトルと本文は環境変数で渡し、XML テキストノードとして構築、コマンドは非表示でタイムアウト 10 秒）、通知クリックのコールバックはない；配信前にテキストを統一して浄化（`Sanitize`、パッケージ実行のネイティブ経路も再利用）：XML 1.0 が受け付けない C0/DEL/C1 制御文字を除去し（そうしないと toast の XmlDocument が全体エラーになる）、タイトル 100 / 本文 300 文字で切り詰める（Windows の環境ブロック総量は 32767 文字で、超過すると CreateProcess が失敗し通知が静かに失われる）。 |
| `core/` | 共有データカーネル（入れ子 module `zakki/core`、サードパーティ依存ゼロのリーフ）：時間トークン（`@`/`~`/`^`）の解析と正規化された書き戻し、繰り返しルールとインスタンス展開、現在のインスタンスと完了の前進（ADR-0002）、原子的なタイムゾーン選択と `RuleSyntaxVersion=1`；`core/zakkicore`（パッケージ名 `zakkicore`）は UTF-16 オフセットとエラーコードを伴う gomobile JSON 境界を提供；`core/model`（パッケージ名 `model`）は zakki.json の共有ディスクモデルにおける単一の真実の源（File/Tab/Settings、バージョン 3 への移行、タブ数上限/既定値の定数を含む）で、デスクトップの `internal/notes` は型エイリアスと転送で消費する。デスクトップの `internal/markdown` と将来のモバイルもこの 1 つの実装から意味論を消費する；層構成の鉄則は [エンジニアリング標準](engineering-standard.md) 第 3 節。 |
| `mobile/binding` / `mobile/ios` | モバイル向けスキャフォールド（**凍結済み**、2026-11-11：[ADR-0003](../adr/0003-pause-mobile-client.md)（中国語）、[モバイルクライアントのアーカイブ](mobile-archive.md)；デスクトップの `make check` におけるルート module のビルドとテストには参加しない）：`mobile/binding` は独立した Go module で、`require zakki/core` と `replace => ../../core` を持ち、golang.org/x/mobile への依存を唯一許されるモジュール（tool directive でバージョン固定）で、`gomobile bind` が `core/zakkicore` を XCFramework／AAR に固める；`mobile/ios` は XcodeGen プロジェクト（`project.yml` から .xcodeproj を生成、生成物とバインディング成果物はコミットしない）で、いかなる Go ビルドにも参加しない。core は依然として依存ゼロのリーフ。 |
| `internal/markdown` | Markdown の解析、フォーマット変換、表の純粋関数（MyGo 依存なし）。時間トークン（`@時刻`、`~事前量`、`^繰り返し`）のインライン認識とその場での更新（`timeinline.go`）および旧行末解析（`rowtime.go`）は `core` に委譲し、本パッケージは呼び出し面のみを保持（`ParseRule` / `Expand` / `Occurrence` / `Advance` の薄い転送を含む）し、インラインコード/リンクの rune 保護域を core のバイト保護域に換算する；`AlertTiers` とポップオーバーは同一の段階ホワイトリストを共有する。 |
| `internal/codehl` | コードブロックを行単位で字句解析して着色する純粋関数：`Kind`（コメント/文字列/数値/キーワード/関数/キー）× インライン `Span`、フェンスの info から言語を正規化（go/js/ts/py/sh/json/yaml/toml/rust/c/java 系、未知の言語は汎用ルール）；行をまたぐ追跡はせず、ブロックコメント/複数行文字列は開始行のみ着色（MyGo 依存なし）。 |
| `internal/notes` | 唯一の正式ファイル zakki.json の `Store`（ディスクモデル、移行、未知フィールドのエンコード/デコードの意味論は `core/model` にあり、本パッケージは型エイリアスと転送で消費する）：`store.go` は読み込み（`model.Decode` 経由：ファイルの存在と元の hadTabs を返し、ディスクのバイト指紋を記憶し、ロック内でトップレベル/settings/tab の三層の未知フィールドのスナップショットを保存；再読み込みに成功すると旧い未書き込みスナップショットと再試行を無効化）、書き込み保護（破損/高バージョン/タブ超過/外部変更のときは書き込みを拒否し、コピーを作らない）とパス状態；`save.go` は `ScheduleSave`（最初の変更で期限を固定し、以降の入力はスナップショットを差し替えるだけで延長しない）、`SaveNow`、終了時の `Shutdown` と失敗時の自動再試行（書き込み時に未知フィールドのスナップショットを組み立てて `model.Encode` を通す：未知フィールドがなければ旧 `MarshalIndent` の出力とバイト単位で同一、未知フィールドは保存をまたいで往復して保持され、削除済みタブの未知フィールドはもう書き出さない）；`relocate.go` は `Relocate` の単一ファイル安全移転；`git_sync.go` / `git_schedule.go` はこの 1 ファイルの正確なパスに対する Git コミットと間隔指定のプッシュ（バックグラウンドの単一 worker、世代ゲート、ローカル書き込みコマンドと移転の排他、プッシュはロックを取らない）；`sync.go` はクラウド同期のループ（まずリモートとバージョン番号を取得 → 待機中の保存を flush + verifyDisk → 判定表 → CAS アップロード/リモート採用/ベースラインのみ更新/自動マージ、CAS 失敗時は再取得して再判定；ローカル段階では writeMu+gitGate を保持して移転・書き込み保護と排他、ネットワークはロックを取らない；ベースラインはデバイスローカルの状態ファイルに保存）、`sync_merge.go` は双方が変更した場合のタブ単位の三者マージ（ADR-0004：ベースラインの原文を共通祖先とし、同一タブを両側が変更した場合は新しい方が勝ち、ダイアログもアーカイブも残さない）、`FinalSync`（終了後の期限付き追加プッシュ）と保存デバウンス/フォーカス時取得/フォーカス喪失時プッシュのトリガ意味論；`sync_github.go` はバックエンド A（GitHub Contents API の blob sha CAS、大ファイルは raw へフォールバック；403/429 はまず `X-RateLimit-Reset` / `Retry-After` を見て待ち時間のヒントを出す；ファイルが 404 のときはリポジトリのプローブで「ファイル欠落」と「リポジトリ権限なし/レート制限」を区別し、プローブ失敗はリモートが空と見なさずそのまま報告；レスポンスが 64MB を超える場合は失敗として扱い、切り詰めた内容を本文として扱わない）；`sync_oauth.go` は Device Flow とトークン更新（refresh token のローテーション、`bad_refresh_token`/`invalid_grant` を「再接続」にマッピング）；`sync_keyring*.go` はシステムの安全なストレージを抽象化（macOS のキーチェーンは security CLI 経由、Windows は DPAPI のユーザー単位暗号化ファイル、他のプラットフォームは明示的に利用不可；トークン供給クロージャが「読み込み→更新→再保存」を直列化し呼び出し元の ctx に従う）。データバージョン 3：組版テーマの旧 ID は読み込み時に `note` へ移行。 |

## スレッドモデル（MyGo のハード制約。違反すると実行時にエラーになるか `go tool mygo vet` に止められます）

- **app の状態はメインスレッドでのみ変更します**。`view` は毎フレーム、メインスレッドで状態を読んで UI を構築します；
  メニュー/トレイ/ホットキーのコールバックは `withWindow` を経てメインスレッドに戻り状態を変更して再描画を起こします；バックグラウンドの完了コールバックは原子的に公開された生存中のウイン
  ドウの `Window.Update` 経由でのみ送出され、ウインドウが閉じられたらそのまま捨てられます。
- **バックグラウンドの書き込みとリマインダー解析は不変スナップショットにしか触れません**。リマインダーはメインスレッドがタブ ID/タイトル/テキストを複製し、
  バックグラウンドがテキストで解析ブロックをキャッシュして投影を計算します；ノートは `snapshotFile`、環境設定は `prefs.Store.TakeSnapshot` で、
  いずれもメインスレッドで値のコピーを取ります；バックグラウンドのタイマーはスナップショットの書き込みのみで、`app` の可変フィールドを読み書きすることは決してありません；
  調整状態は `notes.Store` / `prefs.Store` 内部の mutex にあり、環境設定はさらにリビジョン番号で古い値が新しい値を上書きするのを防ぎます。
- **毎フレーム構築する UI 要素（`ui.*` コントロール）は `app` に保存しません**。`app` に保持するのはウインドウ/メニューといったデスクトップ統合のハンドルのみ（
  `*mygo.Window`、`*mygo.Menu`、`*mygo.MenuItem`）で、通常のフレームをまたぐ状態はすべて普通のフィールドに保存します。
- **スレッドをまたぐ更新には `Window.Update` を使います**。`runOnMain` は原子的に公開された生存中のウインドウを読んで送出するだけです；
  ウインドウが存在しないときはコールバックを実行せず、バックグラウンドの goroutine から直接 `app` の状態を変更することは決してありません。
- 終了フロー（`finishQuit` → `shutdownForQuit`、メインスレッド）：保存タイマーを止める →`stopped` を立てる →最終スナップショットを保存しその完了を待つ。
  ノートと環境設定の両方が成功してから終了します（アップデータの再起動もこのフローを通ります）；いずれかの保存が失敗した場合は終了をキャンセルし、ノート Store を保存受付に戻し、
  メインウインドウを開き直してエラーを表示し、リマインダーのスケジューリングと実時間巡回を復元し、編集の継続と再試行を許します。

## 永続化のライフサイクル

アプリデータのディレクトリは macOS では `~/Library/Application Support/Zakki/`、Windows では `%APPDATA%\Zakki\` です。開発実行では同階層の `Zakki Dev` を使います。

| 内容 | バックアップと同期 |
|---|---|
| `zakki.json` | 唯一のノートファイル。タブの内容と一部のタブバー設定を含みます。既定はアプリデータのディレクトリですが、`storage.dataFile` で場所を変更した場合は実際に使っているファイルをバックアップします。アプリの Git 自動コミットとクラウド同期はこのファイルだけを扱います。 |
| `preferences.json` | アプリの環境設定。設定を引き継ぐ場合は別途バックアップし、別の端末では `storage.dataFile` など端末固有のパスを確認します。 |
| `window-state.json`、`updater.json`、`fonts/` | MyGo のウインドウ状態、アップデータの状態、再取得できるフォントキャッシュ。ノートと一緒にバックアップ・同期する必要はありません。 |
| `sync-state.json` | 前回同期したノートの原文を含む、端末ローカルの同期ベースライン。独立したバックアップではなく、Git に登録したり別の端末へコピーしたりしません。なければ初回同期として扱います。クラウドにノートがあればそれを採用し、なければ既存のローカルノートをアップロードします。 |
| AI キーと GitHub 同期の資格情報 | macOS はキーチェーン、Windows は現在のユーザーの DPAPI で暗号化したファイル（アプリデータ内の `ai-key.bin` と `sync-token.bin`）に保存します。ノートや環境設定には含めず、Git や同期の対象にしません。別の端末ではキーの再保存や再認可が必要です。 |

現在のコードはバージョン 12 より前の `backups/` を読み書きしません。削除前に、残しておきたい古いノートがないか確認してください。

ディスクに残らないもの：

- **ログ**：`setupLogging` は stderr にのみ書き、ログファイルを作りません；`mygo.App.Path(mygo.PathLogs)` も呼びません（呼ぶと
  `~/Library/Logs/Zakki/` を勝手に作ります）。永続化エラーの正直な報告は UI（下部バーの警告、設定ページの状態）に頼り、ログには頼りません。
- **取り消し履歴**：`liveUndo` / `liveRedo` はメモリ内のみで、タブを切り替えるとクリアされ、終了すれば消えます。
- **破損した環境設定のコピー**：既定に戻すときは破損した `preferences.json` を直接上書きし、元のファイルを別に保存しません（「環境設定のライフサイクル」を参照）。
- **クラッシュで残ったテンポラリファイル**：原子的書き込み（`.<ファイル名>.tmp-*`）、移転（`.zakki-relocate-*`）、
  書き込み可能プローブ（`.zakki-write-probe-*`）は正常経路では即座に削除され、書き込みの瞬間にプロセスが強制終了された場合は次回起動時に `sweepStaleTemps` がデー
  タディレクトリとノートファイルのディレクトリから 10 分を超えた残骸を削除します（しきい値は共有フォルダで別プロセスが書き込み中のファイルを避けるため）。
  接頭辞の規則は `atomicfile.TempPrefix`、掃除は `atomicfile.RemoveStaleTemps`。

### 保存（唯一の正式ファイル：`storage.dataFile` が指す `zakki.json`）

1. **期限の固定**：最初の未保存変更から `storage.saveIntervalMs`（既定 2 秒）後に書き込みを開始します；その間に入力が続いても書き込み待ちのスナップショットを差し替えるだけ
   で、期限は延ばしません；変更がなければ繰り返し書き込みません。失敗時は同じ間隔で自動的に再試行します。
2. **永続書き込み**：`notes.Store.writeFile` はまず同一ディレクトリのランダムなテンポラリファイルに書き込み、全体を書き込んで `Sync` / `Close` の後に
   rename し、続いて親ディレクトリを同期します（Windows ではディレクトリ同期を行いません）；置換は完了したがディレクトリ同期に失敗した場合もディスク指紋は更新し保存エラーは保持し、
   再試行では改めて書き込みと同期を行い、成功するまで保存済みとは報告しません。書き込み前に `verifyDisk` でディスクのバイト指紋を照合し、
   ファイルが外部で変更/移動/削除されている場合（`ErrExternalChange`）や書き込み保護中（`ErrSaveBlocked`）は書き込みを拒否して報告し、
   メモリの内容で盲目的に上書きすることは決してありません。
3. **最終保存**：終了（アップデート再起動を含む）は `Shutdown` を経て進行中の書き込みを待ち最終スナップショットを書きます；失敗すれば終了を止め、編集セッションを保ち、
   修正後の再試行を許します。停止後の `SaveNow` は `ErrStopped` を返します；メニューの保存は終了期間中の遅延リクエストを無操作として扱いますが、
   通常の同期呼び出しは未書き込みを引き続き知ることができます。
4. **移転**：保存位置の変更は `Relocate` を通します——既存の移動先への上書きを拒否 → 候補ファイルを書き込んで検証 → 環境設定の永続化に成功してから正式パスを切り替え → 旧ファイル
   を削除；コミット前の失敗は元のパスと元ファイルを保ちます。`RelocateResult.Committed` が切り替えの完了可否を明示し、コミット後の旧ファイル削除や環境設定ディレクトリの同期に失
   敗しても新しいパスを採用して警告を報告します；候補ファイルはハードリンクによる排他的な公開を優先し、ハードリンク非対応の場合は `O_CREATE|O_EXCL` による排他的書き込みと同期、
   読み戻しで検証します；ディレクトリを先に同期してから、環境設定がそのディレクトリを指せるようにします。

### Git（ファイルがリポジトリ内にあり、ユーザーが有効にした場合、そのファイルを直接追跡します）

`git_sync.go` / `git_schedule.go`：バックグラウンドの単一 worker で、コミットとプッシュをそれぞれ間隔でスケジュールします（既定 1 / 10 分、
失敗も 1 回の試行として数えます）；コミットは現在のノートファイルの正確なパスだけを `add`/`commit` し（リポジトリのサブディレクトリと worktree に対応）、
リポジトリの他のファイルやステージ内容には触れません；プッシュする `git push` はブランチの履歴であり単一ファイルに限定できないため、独立したノート用リポジトリを推奨します；
システムの git CLI を呼び（タイムアウト 1 分）、macOS のシム検出、非対話の環境変数、「pull/rebase/force push をしない」は従来の実装を踏襲します；
設定が無効になったとき、書き込み保護中、`Close` 時は世代番号で進行中のタスクを無効化しコンテキストをキャンセルします；非ファストフォワードなどリモートに拒否されたプッシュは
`ErrPushRejected` を報告し、手動同期と衝突解消の後に再プッシュするよう促します；`GitStatus` はリポジトリルート、最終コミット/プッシュ時刻、エラーを公開し、
「保存と同期」ページが表示します。

### クラウド同期（sync.go、スイッチ有効化後に起動）

各ラウンドは「まず取得 → ローカル判定 → CAS コミット」（D12 / ADR-0004）：pull でリモートの内容とバージョン番号を読み（バックエンド A では blob sha）、
ロックを取るローカル段階（順序 writeMu→ gitGate → mu、移転・書き込み保護と排他）でまず書き込み待ちのスナップショットを flush し verifyDisk を行い、
続いて判定表に従って処理します：リモートを採用（verifyDisk 通過時のみ書き込み、書き込み後は保存を凍結して UI の再読み込みを要求し、`Load` で解除）、
ローカルをアップロード（CAS の期待値はこのラウンドで取得したバージョン番号、同一内容のバージョンずれは許容）、ベースラインのみ更新、または自動マージ（双方が変更し内容が異なるとき：
`sync_merge.go` がベースラインの原文を共通祖先としてタブ ID で三者マージし、同一タブを両側が変更した場合は更新時刻の新しい方が勝つ——ローカルファイルの mtime 対リモート最新
コミットの committer 時刻、リモート時刻が取れないときはローカルが新しいとみなす；マージ結果は書き込んでアップロードし、マージ済みを通知する。ダイアログもアーカイブも残さない；
ベースライン原文がない/デコード失敗/タブ上限超過/再検証失敗の場合はファイル全体の新しい方が勝つ方式に退化する）。一度も同期していないデバイスはクラウドを正とし、
歓迎文がクラウドのノートを上書きすることはありません。CAS が拒否された場合は古いバージョン番号で盲目的に再試行せず、再取得して再判定します（上限 3 ラウンド）。
ベースライン（内容指紋 + 前回同期の原文 + バックエンドのバージョン番号 + ローカル/リモートの存在性）はアプリのデータディレクトリの `sync-state.json` に保存し、
破損時は「一度も同期していない」として降格します（クラウドを正とする）。同期を有効にすると `syncActive` ゲートで旧い Git スケジューラを一時停止し（ユーザーの設定はそのまま保持）、
無効にすると保持された設定で復元します。同期トークンはバックエンドの認証に使い、システムの安全なストレージに保存します。ノート、環境設定、同期ベースラインには平文で書き込みません。

### 異常処理（バックアップコピーなし）

- ファイルが存在せず `storage.dataFile` も未設定：初回実行として歓迎テキストを書き込みます。
- 解析失敗 / 読み込み失敗 / バージョンが高すぎる / タブが 9 個を超える：書き込み保護に入り、
  **元のファイルを保ち、書き込みを拒否し、`.pending` / `.corrupt` のコピーを生成しません**；ユーザーがファイルを修正した後に「ファイルを再読み込み」（
  `reloadNotes`）で明示的に復帰します。
- 設定済みのカスタムパスが再起動時に失われた：同じくエラーを報告して書き込み保護し、初回起動として再構築しません。
- 外部プログラムがファイルを変更した：保存前の指紋照合が失敗し、上書きを拒否します；有効な内容を明示的に再読み込みした後に続行します。

### hideOnEscape のキー欠落時は既定 true

設定の他の項目の既定値は false/空文字ですが、`hideOnEscape` だけは既定 **true** です。JSON の bool は「キー欠落」と明示的な `false` を区別できないた
め、`hasHideOnEscapeKey` が `map[string]json.RawMessage` でキーの存在を検出します：キー欠落（settings 全体の欠落を含む）
は true として扱い、明示的な false はそのまま保持します。

## データファイル形式（`savedFile`）

```json
{
  "version": 3,
  "active": 0,
  "tabs": [{ "id": 1, "text": "…", "color": "#…" }],
  "settings": {
    "themeSource": "system",
    "alwaysOnTop": false,
    "hideOnEscape": true,
    "source": false,
    "tabMotionOff": false,
    "tabDotShape": "dot"
  }
}
```

| フィールド | 型 | 意味 |
|---|---|---|
| `version` | int | データバージョン。現在は `currentDataVersion = 3`；0/1 は固定 7 点形式として扱い、より高い場合は読み込みを拒否して上書きしない |
| `active` | int | 現在アクティブなタブのインデックス（読み込み時にタブ数で clamp） |
| `tabs` | [{id,name,text,color}] | 動的タブ（1〜9 個）：安定 ID、任意の名前、markdown のプレーンテキスト、色（空/不正はパレットにフォールバック）；v1 の `dots` フィールドは読み取り専用で保持し、新しい保存では書き出さない |
| `settings.themeSource` | string | `system` \| `light` \| `dark`、空文字は `system` |
| `settings.markdownTheme` | string | 空 / `sonnet` は Sonnet、`note` は付箋（バージョン 2 のファイルにある改名前の旧 ID は読み込み時に新しい ID へ移行） |
| `settings.bodyFont` / `settings.monoFont` | string | 本文 / コードフォントのプリセット、空はテーマ既定 |
| `settings.bodySize` / `settings.lineHeight` | float32 | 本文フォントサイズ / 行の高さ、0 はテーマ既定 |
| `settings.alwaysOnTop` | bool | ウインドウを最前面に固定 |
| `settings.hideOnEscape` | bool | Esc でウインドウを隠す、**キー欠落時は既定 true**（上記参照） |
| `settings.source` | bool | 旧フィールドで読み取り専用；ソース/プレビューの切り替えはセッション状態であり、新しい保存では書き出さない |
| `settings.preview` | bool | 旧版のフィールド、読み込み時のみ `source` に統合し、新しい値は書き出さない |

## 環境設定のライフサイクル

`Run` はまず `resolveDataDir()` を呼んでデータディレクトリを解決します；失敗した場合は Store を構築せず、`WhenReady` でネイティブのエラーを表示して終了しま
す。続いて `loadPreferences` が `preferences.json` を読みます：存在すれば厳格にデコードし（旧バージョンのフィールドの昇格を含む）、
存在しなければ既定値を直接書き込みます——新規インストールでは旧 config ファイルをインポートしません。次に `openConfiguredNotes` が `storage.dataFile`
に従って唯一のノートファイルを開き（空文字 = アプリのデータディレクトリの `zakki.json`）、データを `load` します；設定済みのパスが失われている場合はエラーを報告して書き込み保護
します。実行中のすべての環境設定の変更は `updatePreferences` という統一入口を通ります：検証 → 実行時への適用 →メニュー/ウインドウ/ホットキーの同期 → デバウンス自動保存；
ディスクへの書き込みは `prefs.Store` で直列化し、tmp/rename で原子的に置換し、リビジョン番号で古いスナップショットが新しい値を上書きするのを防ぎます。
`preferences.json` が破損しているかバージョンが先行している場合は復旧待ち状態に入ります：元のファイルを上書きせず、設定ページが「破損したファイルを破棄して既定の設定に戻す」を提供し
ます（元のファイルを直接上書きし、`.bad` コピーは残しません）；復旧に成功した後は現在のセッションが復旧後のパスでノートを直ちに再読み込みし、読み込みに成功して初めて書き込み保護が解除されます。
環境設定のバージョンは現在 **16**：バージョン 16 で非資格情報の `ai` 節を追加（API キーはシステムの安全なストレージにのみ保存）。バージョン 15 で `sync.clientId` を追加（GitHub App の Client ID、資格情報ではない；
空文字は環境変数 `ZAKKI_GITHUB_CLIENT_ID` にフォールバックし、Finder から起動してシェル環境変数が取れない場合でも接続ボタンが永久に押せない状態にならない）；
バージョン 14 でクラウド同期の `sync` 節を追加（「保存と同期」のクラウド同期の小節と `internal/app/sync_bridge.go` の行を参照）；
バージョン 13 で本文領域の左右/上下の内側余白上書きを追加；バージョン 12 で `backup` とデバウンスのミリ秒が `storage` と `git` に置き換わりました（
`internal/prefs` の行を参照）；より古いバージョンのキー昇格の意味論は configuration.md を参照。終了フロー（`shutdownForQuit`）
はノートデータの最終保存の後に環境設定の最終保存を待ち、いずれかの失敗は終了または更新再起動を止めます。完全な契約は [環境設定と設定](configuration.md) を参照；
MyGo アップデータは別途 `updater.json` を管理し、アプリの環境設定の JSON 契約は変えません。
