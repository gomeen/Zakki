# Zakki のリリースと更新

## 現在の方式

- リポジトリと更新配布：公開リポジトリ `gomeen/Zakki` の GitHub Releases を使い、追加のサーバーは不要です。
- アプリ名とインストールパッケージ：macOS は `Zakki.app` / DMG、Windows は `Zakki.exe` / Setup EXE。アプリ識別子は `com.gomeen.zakki`、
  Go module 名は `zakki`；データディレクトリは macOS が `~/Library/Application Support/Zakki/`、
  Windows が `%APPDATA%\Zakki\` で、JSON 構造は変えません。アプリは新規インストールとして扱い、旧データディレクトリの移行は行いません。
- アップデータ：MyGo v0.5.1 の `plugins/updater/native` で、すべてネイティブ UI、webview なし；アプリメニューとトレイの両方が「アップデートを確認…」を提供し、
  既定では手動チェックのみです。ユーザーはバージョン情報の確認、ダウンロードとインストール、スキップ、後で再起動を選べます。
- リリース対象は **darwin/universal**（Intel と Apple Silicon）と **windows/amd64**（Windows 10/11 x64）に固定します。
  同じ Release が `update-darwin-universal.json` と `update-windows-amd64.json` を別々に提供し、2 つのシステムで更新が混ざることはありません。
  アーキテクチャごとに独立したマニフェストに加入するため、後から対象を気軽に切り替えてはいけません（既存バージョンが更新を受け取れなくなります）；現在 Windows ARM64 のネイティブパッケージはリリース
  していません。
- Release の添付：2 つのインストールパッケージ、2 つの署名済み更新アーカイブ、2 つの更新マニフェスト、そして現在の Latest から新バージョンへの署名付き差分パッケージ（`*.delta`）；
  SHA256SUMS は生成しません（完全性はマニフェスト内の Ed25519 署名で担保し、検証に失敗したものはアプリに書き込みません）。`mygo.json` の `updates.deltas` は
  `1`：現在の Latest から新バージョンへの差分パッケージだけを生成し、より古いバージョンは完全なアーカイブを直接ダウンロードします。アプリは一致する delta を優先し、パッチ欠落、サイズ上の利点なし、
  検証失敗、ローカルアプリの改変がある場合は自動で完全な署名済みアーカイブにフォールバックします（このフォールバックは無効化できません）。
- **Apple 開発者アカウントはありません**：`macos.signingIdentity` は `-` で、ad-hoc 署名のみ、公証なしです。Windows も Authenticode コード署名が
  ないため、SmartScreen が未知の発行元を表示する場合があります。両プラットフォームは Ed25519 の更新署名鍵を共用します；これは更新パッケージの出所を検証するものであり、
  Apple や Windows のシステムコード署名の代わりにはなりません。

`.github/workflows/ci.yml` はブランチと PR を検査します；`release.yml` は `vX.Y.Z` tag のプッシュ後に検査とパッケージングを行い、まず全件検査を実行し、
次に macOS と Ubuntu のランナーで 2 つのプラットフォームをそれぞれビルドします；**両プラットフォームが成功**した後にまとめて**ドラフト Release** へアップロードし、
自動公開はしません。いずれかのプラットフォームが失敗した場合はアップロード job を実行せず、成功した側の Actions 添付は引き続き調査に使えます。設定が揃ったからといって公開済みではありません：
Secret の設定、バージョンのプッシュ、ドラフトの公開がなお必要です。

## 初回設定（1 回だけ）

### 1. 更新署名鍵

このプロジェクトの公開鍵は既に `mygo.json` に書かれています。対応する秘密鍵は設定時に生成され、リポジトリの外に保存されています：

```text
~/Library/Application Support/mygo/update-keys/zakki/mygo-update.key
~/Library/Application Support/mygo/update-keys/zakki/mygo-update.pub
```

秘密鍵の権限は `0600` です。秘密鍵はパスワードマネージャーなど安全な場所にバックアップしてください；チャットに貼らず、Git にコミットせず、Release にアップロードせず、
ログにも出力しないでください。秘密鍵を失うとインストール済みバージョンに信頼できる更新を配布できなくなり、漏洩すると更新の偽造に使われ得ます。既存の鍵を置き換えるために keygen を再実行しないでください。

GitHub CLI のログインを済ませた後に、**秘密鍵ファイルの中身**をリポジトリの Actions Secret に書き込みます（ファイルパスではありません）：

```sh
gh auth login
gh secret set MYGO_UPDATER_PRIVATE_KEY --repo gomeen/Zakki \
  < "$HOME/Library/Application Support/mygo/update-keys/zakki/mygo-update.key"
```

ローカル設定の段階では上記の GitHub への書き込みを行いません。リリースワークフローは GitHub 組み込みの `github.token` でアップロードするため、追加の PAT は不要で、
まして Token をアプリに埋め込んではなりません。リポジトリで Actions がワークフロー宣言の `contents: write` 権限を使えることを確認してください。
ソースリポジトリをプライベートにする場合は、別に公開リリース用リポジトリを用意して `updates.github` を同期させる必要があります；現在のアップデータはプライベートリポジトリの資格情報を持ちません。

### 2. 初回コミットとリモート

リモートは `git@github.com:gomeen/Zakki.git`、ブランチは `main` です。設定作業は自動でコミット、tag、プッシュを行いません；変更をレビューし、
作業ツリーの他の修正を確認したうえで自分でコミットとプッシュを行ってください。

## リリースごとの手順

1. **`mygo.json` の `version`** を変更し（唯一のバージョン源）、`CHANGELOG.md` に `## X.Y.Z` の節を追加します。アプリ内の更新説明はこの節から来ます；
   ファイルが存在しても節がない場合はビルドが失敗します。
2. `make check` と `go mod verify` を実行し、README と挙動の変化の説明を同期させます。
3. コードをコミットし、リリース対象のコミットに漏れがないことを確認してから同じ番号の tag を打ちます。以下のコマンドは能動的なリリース操作であり、設定段階では実行しないでください：

   ```sh
   version="$(jq -r .version mygo.json)"
   git push origin main
   git tag "v$version"
   git push origin "v$version"
   ```

4. Actions の `release` ワークフローを確認します。それは：
   - tag、バージョン、リポジトリ、秘密鍵の Secret を照合し、新バージョンが現在の Latest より厳密に高いことを要求します；秘密鍵がない場合やバージョンが後退している場合は直ちに失敗し、
     不完全な配布物を生成しません。
   - `go mod verify` と完全な `make check` を実行します；macOS ランナーが universal パッケージをビルドし、Ubuntu ランナーが NSIS をインストールして
     Windows x64 インストーラをクロスビルドします。
   - インストーラ、マニフェストのバージョン/URL、アーカイブのサイズを検査します；加えて macOS の両アーキテクチャと ad-hoc 署名、Windows の PE x64 実行ファイルを照合します。
   - 現在の Latest バージョンを読み、両プラットフォームのマニフェストと添付がそのバージョンから新バージョンへの有効な delta を含むことを要求し、署名フィールドと実際のファイルサイズを照合します。
   - 両プラットフォームの Actions 添付を保持します；すべて成功したらまとめて再検証し、ドラフト Release にアップロードし、2 つの更新マニフェストを最後にアップロードします。
   - 公開済みの同じ番号の Release の上書きを拒否します；公開済みバージョンの修正は必ずバージョン番号を上げます。
5. ドラフトからダウンロードしてテストし、別の Mac/クリーンなアカウントと実機の Windows 10/11 x64 でインストール、トレイ、グローバルショートカット、中国語入力メソッド、
   保存と再起動を確認します。クロスコンパイルは Windows の実行検収の完了ではありません。初めてアップデータを組み込むバージョンは手動インストールが必要です；その後、
   両プラットフォームでそれぞれ 1 回「インストール済みの旧版 → 新版」の実更新回帰を行います。
6. ドラフトに以下のすべてのファイルが含まれることを確認し、GitHub で **Publish release** をクリックし、**Latest** に設定します（prerelease にしない）。
   公開後にユーザーの「アップデートを確認」でそのバージョンが見えるようになります。Release のページ説明はドラフトで編集でき、アプリ内の説明は CHANGELOG から来ます。

## ビルドと成果物

通常のローカルビルド（アップロードなし）：

```sh
make build            # macOS universal
make build-windows    # Windows x64
```

macOS で Windows インストーラを生成するには NSIS を先にインストールします（`brew install nsis`）、Linux は `sudo apt-get install nsis`；
Windows で MyGoCLI を実行すると、NSIS がない場合はダウンロードしてツールチェーンを検証します。必要なのはネイティブ UI だけで、WebView2 は不要です。
ローカルに NSIS がないと MyGo は警告してインストーラをスキップしますが、EXE と署名済み更新ファイルはクロス生成できます；リリースワークフローはインストーラの存在を必須とします。

更新署名付きのローカルビルド（同様にアップロードなし、Windows は最終行を `make build-windows` に置き換えます）：

```sh
MYGO_UPDATER_PRIVATE_KEY="$(< "$HOME/Library/Application Support/mygo/update-keys/zakki/mygo-update.key")" \
  make build
```

`build/darwin-universal/` のファイル：

| ファイル | 用途 |
|---|---|
| `Zakki.app` | ローカル実行用のアプリパッケージ、Release には直接アップロードしない |
| `zakki-<version>.dmg` | ユーザーの初回インストールまたは手動更新 |
| `zakki-<version>-darwin-universal.tar.gz` | アプリ内更新がダウンロードする署名済みアーカイブ |
| `update-darwin-universal.json` | バージョン、説明、URL、サイズ、署名などの更新マニフェスト |
| `*.delta`（利用可能な旧バージョンがある場合） | 前回の Latest から新バージョンへの差分更新、失敗時は自動で完全なアーカイブにフォールバック |

`build/windows-amd64/` のファイル：

| ファイル | 用途 |
|---|---|
| `Zakki.exe` とリソースファイル | ローカル実行用、Release はインストーラで配布し、裸の EXE は別途アップロードしない |
| `zakki-setup-<version>-amd64.exe` | ユーザー単位のインストーラ；既定で `%LOCALAPPDATA%\Programs\Zakki` にインストール、管理者権限は不要 |
| `zakki-<version>-windows-amd64.tar.gz` | Windows のアプリ内更新用の署名済みアーカイブ、Setup とアンインストーラを含まない |
| `update-windows-amd64.json` | Windows x64 のバージョン、説明、ダウンロード情報、署名 |
| `*.delta`（利用可能な旧バージョンがある場合） | Windows の差分更新、失敗時は自動で完全なアーカイブにフォールバック |

差分パッケージは「現在の Latest → 新バージョン」をベースラインとします；アプリは一致する delta を優先しますが、パッチ欠落、サイズ上の利点なし、検証失敗、
ローカルアプリの改変がある場合は自動で完全な署名済みアーカイブにフォールバックします。この安全フォールバックは無効化できません。ダウンロードと展開はいずれも更新マニフェストの Ed25519 署名で検証し、
検証に失敗した場合はインストールを断念して通知します。

MyGo は秘密鍵がない場合に警告して macOS/Windows の更新ファイルをスキップするだけなので、ローカルの通常ビルドは引き続き使えますが、そのインストールパッケージを完全な更新リリースと見なすことは
できません。ワークフローは秘密鍵と成果物を検査し、公開鍵と秘密鍵が一致しない場合はビルドが失敗します。DMG の生成には macOS が必要です；Windows は macOS/Linux からクロスビルドでき、
インストーラには NSIS が必要です。

更新マニフェストの入口：

```text
https://github.com/gomeen/Zakki/releases/latest/download/update-darwin-universal.json
https://github.com/gomeen/Zakki/releases/latest/download/update-windows-amd64.json
```

ソースのアップロードや tag の作成だけ、DMG だけ、ドラフト未公開、Latest 未設定では、いずれも使える正式な更新にはなりません。現在の設定は prerelease を検査しないので、
正式チャネルの tag でプレリリース版をテストしないでください。

## ユーザーのインストールと更新

- **macOS の初回インストール**：DMG をダウンロードし、`Zakki.app` を `/Applications` または自分の `~/Applications` にドラッグします。
  読み取り専用の DMG 内から直接自己更新はできません；インストール先のディレクトリは書き込み可能でなければなりません。開発モードでも自己更新はできません。
- **Windows の初回インストール**：`zakki-setup-<version>-amd64.exe` をダウンロードし、ユーザー単位で既定のディレクトリにインストールします。
  カスタムディレクトリも書き込み可能でなければならず、管理者権限を要する Program Files へのインストールは推奨しません。データは `%APPDATA%\Zakki\` にあり、
  アプリの更新で置き換わることはありません；データディレクトリをプログラムのインストール先にしないでください（アンインストーラがインストール先を削除します）。
- **より古いバージョンのユーザー**：まず保存して旧版を完全に終了し、旧版のデータを別途バックアップします。Zakki は改名前の旧データディレクトリを走査も自動移行もしません；
  新版をインストールした後は想定したデータファイルが使われていることを確認し、同じデータを 2 つのバージョンで同時に書き込まないでください。
- **以後の更新**：Zakki → アップデートを確認… → 説明を見る → ダウンロードしてインストール → 再起動。更新はアプリパッケージを置き換え、現在のバージョンのノートと環境設定は削除しません；
  再起動は終了時の最終保存を経由し、保存に失敗すると終了がキャンセルされてエラーが表示されます。
- **Windows のセキュリティ警告**：現在 Authenticode は未設定のため、SmartScreen/未知の発行元の警告が出る場合があります；ダウンロード元を確認してから実行するか判断してください。
  後から Windows コード署名証明書を別途設定できます。Apple 開発者アカウントと既存の更新鍵とは独立しています。
- **ネットワークや権限の問題**：更新ウインドウに失敗または利用不可と表示されます；GitHub へのアクセス、インストール先の書き込み権限を調べ、必要なら完全に終了してから新しいインストーラを実行するか、
  アプリを上書きしてください。
- **macOS のセキュリティ警告**：現在 Developer ID の信頼と公証がないため、初回起動が Gatekeeper に止められる場合があります。
  入手元を確認したうえでシステムの「プライバシーとセキュリティ」から許可して開いてください；Gatekeeper を全体で無効にしないでください。更新署名はシステムのブロックを取り除くことを保証しないため、
  正式に対外リリースする前に開発者アカウントを取得し署名と公証を整えることを勧めます。

## リリース検収

- [ ] `mygo.json` と tag が同じ番号で、CHANGELOG に対応する節があり、`make check` と `go mod verify` が通る。
- [ ] Secret が現在の公開鍵に対応し、秘密鍵は独立した安全なバックアップがあり、Git と添付のいずれにも秘密鍵がない。
- [ ] macOS と Windows のビルド job がともに成功し、ドラフトに DMG、Setup EXE、2 つの署名済みアーカイブ、2 つの更新マニフェスト、両プラットフォームの delta が含まれ、余分な添付がない。
- [ ] Intel / Apple Silicon のインストールが起動する；実際にダウンロードしたファイルで Gatekeeper の挙動を検証し、ローカルの隔離マークのないパッケージで代用しない。
- [ ] Windows 10/11 x64 でユーザー単位インストール、起動、中国語入力メソッド、トレイ、ショートカット、終了が実機で合格し、SmartScreen の警告を確認する；クロスコンパイルだけで検証済みと宣言してはならない。
- [ ] 旧版のアップデート確認でダウンロード、インストール、再起動ができる；両プラットフォームのマニフェストが前回の Latest バージョンからの delta を含み、添付が存在してサイズが一致する。
- [ ] 更新の前後でノートと環境設定が保持される；保存失敗時に静かに再起動しない。
- [ ] Release を公開して Latest に設定した後、マニフェストとアーカイブを匿名でダウンロードできる。
