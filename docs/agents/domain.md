# Domain Docs

Zakki uses a single context. Before exploring the codebase, read [GLOSSARY.md](../../GLOSSARY.md) and any relevant decisions in [docs/adr/](../adr/).

If a domain document is absent, proceed silently. The `/domain-modeling` skill creates glossary entries and ADRs as terms and decisions are resolved.

Use the glossary's terms in issue titles, refactor proposals, hypotheses, and test names. When a concept has no glossary entry, check whether the project already has a term for it or raise the gap with `/domain-modeling`.

When a proposal conflicts with an ADR, cite the ADR and explain why the decision is worth revisiting.
