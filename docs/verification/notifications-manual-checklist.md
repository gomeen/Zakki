# 通知人工验证清单：Windows 实机 / macOS 通知中心

对应 issue「验证：Windows 通知实机与通知中心显示确认」。背景见
docs/reports/2026-10-28-review-remediation-verification.md：Windows 原生通知长期只有
单测、超时回归与交叉编译证据，缺实机验证。通知通道在 ADR-0005 后改为 MyGo 原生通知
（macOS `UNUserNotificationCenter`、Windows 托盘气泡），图标、来源与点击行为都变了，
清单随之改写。本清单供在真实设备上逐项执行并记录结果，完成后归档到 `docs/verification/`。

## 准备

- 被测构建：待验证 commit 的干净构建，记录 commit hash。必须用打包产物——裸
  `go build` / `go run` 没有应用包，会走 `internal/sysnotify` 回落通道（osascript /
  PowerShell），验证不到原生通道：
  - Windows：`go tool mygo build -platform windows/amd64`（产物在 `build/windows-amd64/`）
  - macOS：`go tool mygo build -platform darwin/universal`（产物在 `build/darwin-universal/`）
- Windows 实机一台（Windows 10 21H2+ / Windows 11），系统通知总开关开启，且未开启
  「专注助手/勿扰」拦截。
- macOS 实机一台：首次通知会弹系统授权询问，选「允许」，再到系统设置 > 通知 > Zakki
  确认横幅与通知中心均开启。
- 触发方式：在笔记中写一条 1–2 分钟后的提醒——内联时间令牌必须显式带 `~` 提前量，
  且提前量只能取白名单 `~0m` / `~5m` / `~10m` / `~30m` / `~1h` / `~1d`（白名单外的值如
  `~1m` 会使整个令牌按普通文本处理，不会发通知）。推荐准点 `~0m`，如
  `记得带伞 @2026-11-17 11:23 ~0m`；只有 `@` 无 `~` 不发通知，任务已完成或 `fireAt` 已过也不发，
  见 docs/adr/0001-inline-time-tokens.md。等待 reminders 触发；提醒依赖应用存活，
  触发期间保持 Zakki 运行。通知没有绕过 reminders 的独立触发入口，若未弹出先排查
  令牌写法，再判定通知路径失败。
- 相关实现：`internal/app/notify.go`（打包运行的原生通道、通知 ID 与点击定位）；
  `internal/app/reminders.go`（何时发）；`internal/sysnotify/`（未打包运行的回落，
  macOS osascript / Windows PowerShell，点击无回调）。

## Windows 实机验证点

### W1 toast 正常显示
- 步骤：双击 `zakki.exe` 启动，创建 1 分钟后的提醒并等待触发。
- 预期：桌面右下角弹出 toast，标题显示 Zakki、正文与提醒内容一致。
- 注意：这条走的是托盘气泡（ADR-0005），Win10+ 由系统转成 toast。是否留在通知中心
  **需实测并记录**，不再预设为通过标准。
- 结果：[ ] 通过 [ ] 失败（现象/截图；是否留在通知中心：）

### W2 来源与图标是 Zakki
- 步骤：分别以 1) 资源管理器双击、2) PowerShell `.\zakki.exe`、3) cmd 启动，各触发一次通知。
- 预期：三次通知的来源均为 Zakki 自己的名称与托盘图标，不随启动方式漂移；不再出现
  「Windows PowerShell」。通知中心按同一应用分组（行为记录在备注里）。
- 说明：这一项取代旧的「固定 AUMID 生效」验证（ADR-0005 后不再走 PowerShell AUMID）。
- 结果：[ ] 通过 [ ] 失败（实际来源名/图标：）

### W3 控制台不闪
- 步骤：从资源管理器双击启动（不经终端），触发通知，注视屏幕与任务栏。
- 预期：触发瞬间无黑色控制台窗口一闪而过。原生通道不再调用 PowerShell，本条用于
  确认没有回归到 shell 投递。
- 结果：[ ] 通过 [ ] 失败（现象：）

### W4 中文和 emoji 正文
- 步骤：创建提醒，标题固定为「Zakki」，正文混排中文与 emoji（如「记得带伞 ☔️ ✅ 🎉」），
  触发通知。
- 预期：toast 上中文与 emoji 显示正确，无乱码、无「□」占位。
- 实现约定（ADR-0005 后两通道共用）：投递前统一净化文本——删除 XML 1.0 不接受的
  C0/DEL/C1 控制符，并按标题 100 / 正文 300 字符截断（Windows 环境块上限 32767 字符）。
  超过 300 字的段落应看到「…」结尾且通知仍正常弹出；正文里的控制符不应导致整条通知丢失。
- 结果：[ ] 通过 [ ] 失败（现象：）

### W5 点击通知回到提醒条目
- 步骤：触发提醒；先最小化或隐藏 Zakki，再点击 toast。
- 预期：Zakki 前置显示，切到提醒所属标签，光标停在那条提醒所在行（行末）。
  若该标签在触发后被删除，只前置窗口。
- 结果：[ ] 通过 [ ] 失败（现象/截图：）

### W6 同一实例不重复堆叠
- 步骤：围绕同一个提醒反复编辑正文但不动时间，等待触发。
- 预期：只出现一条通知（同一 ID 替换），正文为最新版本。
- 结果：[ ] 通过 [ ] 失败（现象：）

## macOS 通知中心

### M1 横幅与通知中心显示
- 步骤：启动 `.app`，创建 1 分钟后的提醒并等待触发；横幅消失后打开通知中心。
- 预期：
  - 横幅：标题显示 Zakki、正文排版正常，中文与 emoji 不乱码；
  - 图标：显示 Zakki 自己的应用图标，来源为 Zakki（不再是 Script Editor）；
  - 通知中心列表：同一条通知出现；展开后正文完整（不超过 300 字的截断规则）。
- 结果：[ ] 通过 [ ] 失败（现象/截图：）

### M2 点击定位
- 步骤：点击横幅或通知中心里的同一条通知；分别在「窗口在前台」「窗口已关闭」「应用
  已退出后从通知中心点击」三种情况下各做一次。
- 预期：前置 / 重开窗口，切到提醒所属标签，光标定位到提醒条目；标签已删除时只唤起窗口；
  源码模式下只切标签，不改选区。
- 结果：[ ] 通过 [ ] 失败（现象/截图：）

### M3 未授权如实提示
- 步骤：系统设置 > 通知 > Zakki 关闭「允许通知」，再触发一条提醒。
- 预期：不弹横幅；应用内出现一次「系统通知未允许，提醒只在应用内显示」的气泡，
  同一次会话内不重复刷屏；重新允许后，下一条提醒恢复正常投递（不需要重启）。
- 结果：[ ] 通过 [ ] 失败（现象：）

### M4 退出后不提醒（回归）
- 步骤：安排 2 分钟后的提醒，退出 Zakki，等待过点。
- 预期：没有任何通知（ADR-0001：提醒依赖应用存活，OS 级调度未实现）。
- 结果：[ ] 通过 [ ] 失败（现象：）

## 回落通道（可选，开发用）

裸 `go run` / `go test` 走 `internal/sysnotify`。在 macOS 上应看到 Script Editor 来源、
无点击回调；Windows 上应看到「Windows PowerShell」来源。行为与 0.6.3 相同，不属于
发布验收项。
